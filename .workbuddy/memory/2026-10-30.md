## 修复：「什么都识别不到」根因 + 全链路日志

现象：设备上语音点餐始终无结果，logcat 里也没有识别器任何日志。

排查与根因：
1. 识别器原先只在出错时打日志，正常流程静默 → 已补齐全链路日志（TAG `CloudSpeechRecognizer` + `MainActivity`）。
2. **真正的根因（关键 bug）**：讯飞 `dwa=wpgs`（动态修正）模式下，**每帧返回的是「片段」而非累计全文**，最后一帧只有标点 `。`。原代码取「最后一帧」当结果 → `finalText` 永远只有 `。` → `parsedCommands=0` → 界面提示「没有识别到点餐内容」，看起来就是「什么都识别不到」。
   - 日志证据：`[苹果] → [苹果上面] → [屏幕上面的] → [。]`。
   - 修复：按官方 `sn` 有序累积片段，`pgs=rpl` 时按 `rg` 区间替换、`apd` 追加；新增 `joinSegments()` / `appendSmart()` 做中英文智能拼接（拉丁词补空格、中文不补）。修复后 finalText 正常变为完整句子。

其他改进（`CloudSpeechRecognizer`）：
- 采集音源改为优先 `VOICE_RECOGNITION`（source=6，自带 AGC，实测电平明显更高），失败退回 `MIC`/`DEFAULT`；日志打印实际使用的 source。
- VAD：语音起点需连续 3 帧（约 300ms）才确认，避免点击噪声误触发；静音断句 1200ms→1500ms；新增 `NO_SPEECH_TIMEOUT_MS=8000`（一直没说话也会把已录音频送识别）；**始终缓冲音频**（不再只在 RMS 超阈值时才写），避免阈值不合适导致零数据。
- `stop()` 内 join 自身线程的 1s 卡顿已规避。
- 全链路日志点：start/音源/缓冲区大小、每 500ms 的 `rms/peak/loud/voice/buf`、语音起点、自动停止原因、捕获 PCM 字节数、TLS 握手/cipher、Upgrade 101、发送帧数、每帧原始 JSON(400字符)+`sn/pgs/segment/cumulative`、最终 transcript、解析到的商品与数量。

测试限制：无法远程对着麦克风说话，只能 adb 模拟点击（采到的是环境噪声，讯飞会瞎猜，但链路与累积逻辑已验证）。真语音需用户在设备上说一句后再看日志。

## 重大升级：流式识别 + 讯飞在线播报 + 离线语音唤醒（已真机闭环验证）

用户实测反馈：识别已可用，但「一定要语音播报」「要语音唤醒」。三个问题一次解决：

### 1) 识别改为流式（修「永远录满 20 秒」）
- 原实现本地 RMS 门限判断起停，但这台板环境底噪极大（静音段 rms 也能到 2000+，且周期性出现尖峰），静音断句永远不触发 → 每次录到 20s，还得再点一次麦克风。
- `CloudSpeechRecognizer` 重写为**边录边传**：每 100ms 一帧（`status 0→1`）实时发给讯飞，由服务端 `vad_eos=2000` 判断句末，收到 `status=2` 立刻停止录音。中间结果实时 `onPartialResult` 回显。
- 兜底：8s 无说话 / 8s 无有效语音 / 20s 上限；用户再点麦克风也会发结束帧并收回结果（`stop()` 带 6s 看门狗强断连）。

### 2) 语音播报（关键是"必须出声"）
- 板子**没有系统 TTS 引擎**，离线 Sherpa 又要 100MB+ 模型且念不了英文 → 改用**讯飞在线语音合成 `tts-api.xfyun.cn/v2/tts`**（同一套 HMAC 签名，零模型体积）。
- 已用账号实测：`xiaoyan`(中文) / `aisjiuxu`(英文) 均返回音频。中文播报默认 `xiaoyan`，英文 `aisjiuxu`，德语暂用英文音色兜底。
- 新增 `XunfeiTtsEngine`（`aue=raw` 流式 PCM → AudioTrack），沿用 myAPK SherpaTtsEngine 的三条经验：媒体音量为 0 时拉起、`setPreferredDevice` 到板载扬声器（本机输出只有 type=2）、写完等 `playbackHeadPosition` 追上再 release。
- `VoiceAnnouncer` 重写为三级通路：讯飞在线 → 系统 TTS → Toast；`isBusy()` 供唤醒避让。

### 3) 语音唤醒（离线关键词）
- 从 GitHub 下 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M`（int8 三件套 + tokens，**仅 4.9MB**），放在 `app/src/main/assets/kws/`，首启复制到 `filesDir/kws` 按文件路径加载（assets 与文件路径不能混用）。
- 新增 `WakeWordDetector`（`com.k2fsa.sherpa.onnx.KeywordSpotter`），16k/100ms 分片 `acceptWaveform → decode → getResult`，2s 冷却防重复触发。
- 唤醒词在 `SpeechConfig.WAKE_WORDS`：`你好点餐` / `你好点单`（拼音音素 + @中文）。**注意 tokens 只含拼音音节**，换词必须能在 `assets/kws/tokens.txt` 里找到全部音素。
- 唤醒与识别共用麦克风，互斥：`pause()` / `resume()`；播报期间不恢复监听（`isBusy()` 轮询），避免把自己的声音当唤醒词。
- 长按麦克风 = 开关唤醒；启动时自动申请录音权限并开始常驻监听。

### 4) 依赖与构建
- `app/libs/sherpa-onnx-1.12.20.aar`（本地引入）。**坑**：sherpa 的配置类由 Kotlin 编译，非空参数不能传 null（`OnlineModelConfig` 传 null 会抛 NPE），要传空对象 `new OnlineParaformerModelConfig()` 等 4 个。
- 不要再手动放 kotlin-stdlib.jar：androidx 已带入 2.0.21，重复会 `mergeDebugJavaResource` 冲突。
- `androidResources { noCompress += ['onnx'] }`；APK 体积涨到 **96MB**（含 arm64+armv7 的 ONNX Runtime）。
- 通用 WS 客户端抽成 `XunfeiWebSocket`（iot/tts 共用，发送加锁支持收发并行）。
